FAQ
===

Does Ka Extensions for OpenCart 4 work with OpenCart 3?
-------------------------------------------------------

No. Ka Extensions for OpenCart 3 is a separate product with its own version and API.
This documentation applies to Ka Extensions for OpenCart 4.x only.

Which OpenCart 4 versions are supported?
----------------------------------------

OpenCart 4.1.0.3 and newer 4.1.x versions. OpenCart 4.0.x is not supported.

Why is the archive called ``ka_extensions.ocmod.zip`` without a version?
------------------------------------------------------------------------

OpenCart 4 uses the archive name as the extension code and the name of its directory. Ka Extensions
must be installed into ``extension/ka_extensions/``, and a module ``my_module`` into
``extension/my_module/``.

Where is kamod.ini?
-------------------

It is not used in OpenCart 4. Module information is taken from ``install.json`` (see :doc:`install_json`).

Where are generated kamod classes stored?
-----------------------------------------

In ``system/storage/cache.kamod/`` (``DIR_STORAGE``): PHP classes in ``opencart/...`` and templates in
``templates.default/`` (``templates.<store_id>/`` for templates changed in the Theme Editor). You can browse
it to see the class chains generated by kamod. Kamod messages are written to ``kamod.log`` in the logs
directory.

How do I rebuild the kamod cache?
---------------------------------

The cache is rebuilt automatically on the next request after a module is installed or uninstalled on the
Ka Extensions page, after an extension is installed or uninstalled on the *Installer* page and after a change
in the Theme Editor. To rebuild it manually, delete ``system/storage/cache.kamod/valid.kamod``. During
development define ``KAMOD_DEBUG`` (see :doc:`useful_constants`).

My kamod class is ignored. What should I check?
-----------------------------------------------

- The module is installed on the *Extensions > Ka Extensions* page and ``extension/<module>/active.kamod``
  exists.
- The path in the ``kamod`` directory repeats the path of the original file (``kamod/admin/...``,
  ``kamod/catalog/...``, ``kamod/system/...``, ``kamod/extension/<module>/...``). Missing target files are
  listed in ``kamod.log``.
- The kamod cache was rebuilt (see above).
- The namespace of the class is unique (see :doc:`overriding_core_files`).
- The admin area is not in :doc:`safe_mode`.
- The same file is not changed by OCMOD (see :doc:`ocmod`).

A page is empty after my template change. Why?
----------------------------------------------

Ka Extensions renders a template with a twig error as an empty string. Define ``KAMOD_DEBUG`` to see
the error message.

What does the ambulance icon in the admin header mean?
------------------------------------------------------

It is added by Ka Extensions. The red counter shows the number of lines in ``kamod.errors.log``
(errors of kamod and kapatch). The log is cleared when the kamod cache is rebuilt.
