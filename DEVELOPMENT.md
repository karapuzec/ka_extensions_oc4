# Development

The repository is a complete OpenCart 4.1.0.3 store with Ka Extensions for OpenCart 4.

- `extension/ka_extensions/` - the code of Ka Extensions, it is the contents of the package.
- `extension/mod1/`, `extension/mod2/` - test modules: `mod2` changes a model of `mod1` through
  `kamod/extension/mod1/...` (see `docgen/guides/overriding_other_modules.rst`).
- `extension/oc_*_example/`, `extension/opencart/` - extensions of OpenCart.
- `extension/ocmod/` - files generated by OCMOD (*Modifications > Refresh*).
- The admin directory is `admin1/`, the storage directory is `system/storage1/`, the OpenCart installer is
  renamed to `_install/`.
- `tests/` - install tests, `docgen/` - documentation. They are not included in the package.

## Dev store from the repository

1. Clone the repository into the web server folder.
2. Create the database and import the dump:
   ```
   mysql -u root < sql/dump.sql
   ```
   `sql/dump.sql` creates the database `ka_ext_oc4103` itself. `sql/dump_data.bat` re-creates the dump.
3. Config files are not in git (`.gitignore`). Copy the samples and fix `HTTP_SERVER`, `HTTP_CATALOG`,
   `DIR_OPENCART` and the database access:
   ```
   copy config.sample.php config.php
   copy admin1\config.sample.php admin1\config.php
   ```
4. Create writable folders in `system/storage1/`: `cache`, `logs`, `session`, `upload`, `download`,
   `marketplace`, `backup` (only `vendor` is in git), and make `image/cache/` writable.
   Kamod creates `cache.kamod` and `theme.kamod` there itself.
5. `system/config/kamod.php` is tracked with `admin_dir = 'admin1'`. Kamod rewrites it on every cache rebuild
   in the admin area, do not commit local changes of it.
6. `system/framework.php` already contains the lines added by Ka Extensions and `extension/ocmod/system/framework.php`
   starts kamod, so kamod works right after the setup. Open *Extensions > Modifications* and
   *Extensions > Ka Extensions* in the admin area to check it.
7. For development define `KAMOD_DEBUG` in `config.php` and `admin1/config.php`: the kamod cache is rebuilt
   on every request (see `docgen/guides/useful_constants.rst`).

The dev store has a fixed OpenCart version. Check releases on clean stores of the supported versions
(4.1.0.3 and newer 4.1.x) with the install tests below.

## Building the package

The package is `ka_extensions.ocmod.zip` with the contents of `extension/ka_extensions/` at the archive root,
without `active.kamod`. OpenCart 4 takes the extension code from the archive name, so do not add a version
to it.

```
pack_ka_extensions.bat
```
(Windows, `zip` in `PATH`) or on any system with PHP:
```
php tests/build-package.php ka_extensions.ocmod.zip
```

Both pack the files of the working copy, including uncommitted changes. `pack_mod1.bat` and `pack_mod2.bat`
build the test modules.

## Release

1. Update the version in `extension/ka_extensions/install.json`, `ControllerInstaller::$ka_extensions_version`
   (`extension/ka_extensions/system/controller_installer.php`), `changelog.txt` and
   `readme.ka_extensions.txt`.
2. Build the package.
3. Run the install tests on the supported OpenCart versions.

## Tests

`tests/run.php` builds the package, installs a clean OpenCart store, installs Ka Extensions through the admin
area, checks the menu, pages and logs and uninstalls it. It needs PHP CLI and a MySQL user that can create
databases. See `tests/README.md`:
```
export KA_TEST_DB_USER=ka_test KA_TEST_DB_PASSWORD=...
php tests/run.php --oc=opencart-4.1.0.3.zip
```

## Documentation

`docgen/` contains the phpDocumentor configuration, the template and hand-written guides
(`docgen/guides/*.rst`, reStructuredText, listed in `docgen/guides/index.rst`). Generate the documentation
from the `docgen` folder:
```
php phpDocumentor.phar
```
(`gen.bat` does the same). The result is written to `tmp_pack/docs/`.
